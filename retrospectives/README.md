# retrospectives/ — журнал сессий

Файл на сессию: `retrospectives/YYYY-MM-DD_HH-MM_название.md` по [TEMPLATE.md](TEMPLATE.md).

## Зачем

В проекте уже есть память агента (`memory/`), ADR (`docs/architecture/`) и `docs/known-issues.md`. Ретро закрывает то, чего в них нет: **что было / что стало и что можно было сделать лучше** — по конкретной сессии, с датой.

Разделение, чтобы не расползалось:

| Куда | Что туда |
|---|---|
| `retrospectives/` | ход конкретной сессии, ошибки подхода, «в следующий раз сразу дал бы такой промпт» |
| `docs/architecture/` | решение, которое переживёт сессию (ADR) |
| `docs/known-issues.md` | воспроизводимый дефект, который пока не чиним |
| `memory/` | факт о проекте или обо мне, нужный в *следующих* сессиях |
| `plans/*.md` → «Итог» | статус трека: что доделано, что нет |

## Когда писать

В конце сессии, где что-то менялось в коде или в решениях. Не после каждого вопроса.

Ретро на 10 строк, написанное сразу, полезнее подробного, которое не написано.
