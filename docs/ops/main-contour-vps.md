# Основной контур — три потока на VPS

**Дата:** 2026-09-06
**Ветка:** `fix/streams-config-and-execution`
**Счёт:** 1100137867, AlfaForexRU-Real, ~1964 $

## ⚠️ Один счёт — один запущенный экземпляр

Счёт 1100137867 работает **только на VPS**. Ноутбук остаётся машиной для
разработки: тесты MT5 не трогают, но `python main.py` здесь поднимать нельзя.

Два экземпляра на одном счёте ломают всё сразу и тихо:

- Они не видят друг друга. `registry.open_count()` считает открытые потоки по
  набору в памяти **своего** процесса, поэтому лимит «одна открытая позиция»
  превращается в две — по одной на экземпляр.
- Magic-номера совпадают. Позицию, открытую одним, второй считает своей:
  `PositionMonitorAgent` отработает закрытие чужой сделки, запишет причину в
  своё состояние стратегии и заблокирует переоткрытие не в том процессе.
- Пик equity и стоп по просадке считаются дважды и расходятся: у каждого
  экземпляра свой `portfolio_state.json`.

Технической защиты от этого нет и не будет дёшево: два процесса на разных
машинах не имеют общего состояния, а MT5 API не сообщает о других
подключениях к счёту. Это дисциплина, а не проверка в коде.

Автозапуска на ноутбуке нет (ни службы, ни задачи планировщика, ни .bat) —
случайно бот там не поднимется.

## Развёртывание на VPS

Инфраструктура — по `docs/ops/provisioning-runbook.md`. Специфика:

```powershell
# бот остановлен
git status                       # убедиться, что своих правок нет
git fetch origin
git checkout fix/streams-config-and-execution
git pull

# рабочий конфиг потоков не версионируется — заменяем эталоном
Copy-Item streams.json "streams.backup\streams-before-2000.json"
Remove-Item streams.json

# состояние от прежнего счёта
Remove-Item strategies\runtime_state.json -ErrorAction SilentlyContinue
Remove-Item signals\signals.db* -ErrorAction SilentlyContinue
Remove-Item portfolio_state.json -ErrorAction SilentlyContinue
```

`streams.load()` при отсутствующем рабочем файле поднимает состав из
`config/streams.reference.json` (три потока, лот 0.01) и сохраняет его сам.

Зависимости не менялись — `pip install` не нужен.

Дальше `.env`: логин/пароль/сервер счёта 1100137867. `MT5_PATH` можно не
задавать — креды передаются в `initialize()` всегда, а подключённый счёт
сверяется с `MT5_LOGIN`; при несовпадении старт останавливается.

## Проверка перед стартом

```powershell
python -m portfolio
```

Ожидается: лимит одновременных позиций 1, стоп по просадке 40 %, базовый
капитал 2000, блокировки нет. Если `deposit` разойдётся с балансом счёта
больше чем вдвое, `main.py` не стартует и скажет, что смотреть.

После запуска состояние просадки видно на дашборде: баннер скрыт, пока
спокойно, жёлтый на 30 %, красный после остановки торговли.

## Что мерить

- `python -m signals.report [дней]` — сколько сигналов не дошло до рынка.
  Доля `PORTFOLIO_LIMIT` показывает, насколько лимит режет поток входов;
  это первая возможность сверить живое поведение с моделью, где «лимит 1»
  считался отдельной симуляцией, а не этим кодом.
- Разрыв по `combined_a_plus` (август: live −290 против +1785 модельных)
  так и не объяснён.
