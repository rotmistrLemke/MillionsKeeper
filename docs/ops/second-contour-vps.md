# Второй контур — семь потоков на отдельном VPS

**Дата:** 2026-09-06
**Ветка:** `test/seven-streams-vps`
**Статус:** конфиг готов, счёт не заведён

## Зачем

Состав из семи потоков (шестёрка с плюсом в каждом из пяти кварталов плюс
контртрендовая `ema50_overstretch`) был снят с основного контура **не потому,
что плох**, а потому что не помещается в депозит 1964 $: семь позиций
резервируют 1551 $ маржи, и в пик просадки уровень маржи уходит под margin call.

Вопрос «работает ли этот состав живьём» остался без ответа. Второй контур
существует ради него — и только ради него.

## Чем отличается от основного контура

| | основной | второй |
|---|---|---|
| ветка | `fix/streams-config-and-execution` | `test/seven-streams-vps` |
| счёт | 1100137867, 1964 $ | отдельный, от 5000 $ |
| потоков активно | 3 | 7 |
| лот | 0.01 | 0.01 |
| лимит позиций | 1 | **нет** (это и есть эксперимент) |
| стоп по просадке | 40 % | 35 % |

Лимита во втором контуре нет намеренно: с лимитом 1 он повторял бы основной и
отвечал бы на уже отвеченный вопрос.

## Развёртывание

Инфраструктурная часть — по `docs/ops/provisioning-runbook.md` (1 VPS : 1 счёт,
bare Windows, бот как worker). Специфика этого контура:

1. **Счёт от 5000 $.** Ниже состав не помещается: 7 × 0.01 лота = 1551 $ маржи
   (31 % от 5000), модельная просадка 1163–1316 $ (23–26 %), уровень маржи в
   худшей точке около 237 %. На 4000 $ запас исчезает.
2. **`.env`** — логин/пароль/сервер нового счёта. `MT5_PATH` не обязателен:
   креды передаются в `initialize()` всегда, а подключённый счёт сверяется с
   `MT5_LOGIN` (`authenticator.MT5Auth._verify_account`).
3. **`config/portfolio.json`** — подставить фактический баланс в `deposit`.
   При расхождении больше чем вдвое старт остановится с явным сообщением
   (`portfolio.assert_deposit_matches`). Это защита от запуска конфига одного
   контура на счёте другого.
4. **`streams.json`** на VPS создавать не нужно: при пустом или отсутствующем
   рабочем файле `streams.load()` восстанавливает состав из
   `config/streams.reference.json`.
5. **Проверка перед стартом:** `python -m portfolio` должен показать
   «лимит: нет», стоп 35 %, депозит равный балансу счёта.

## Что мерить

Контур запущен ради сравнения с моделью, поэтому смотреть надо не только P&L:

- `python -m signals.report [дней]` — сколько сигналов не дошло до рынка и
  почему. На основном контуре ожидается много `PORTFOLIO_LIMIT`, здесь — ноль;
  всё остальное сравнимо между контурами напрямую.
- Разрыв по `combined_a_plus` (август: live −290 против +1785 модельных)
  так и не объяснён. Семь потоков дают вторую независимую выборку по нему.
- Флэт-фильтр `BaseStrategy.is_flat()` работает в live и отсутствует в
  `backtest_engine`; он гасит 44 % баров у `cci_rsi`, `triple_ema`,
  `ema_pullback`. Сравнивать эти три с бэктестом некорректно, пока не выровнено.

## Чего не делать

Не сливать эту ветку в `main` вместе с основным контуром: `config/` у них
конфликтует по смыслу, а не только по тексту. Общий код (портфельные
ограничения, сверка счёта, журнал отказов, баннер) должен попадать в `main`
из основной ветки, а эта остаётся с одним отличием — своим `config/`.
